INTRODUCCIÓN 
El backend de este proyecto tiene como objetivo proporcionar la lógica y el soporte necesario para un simulador educativo de sistemas de energía solar para el módulo de Gestión del montaje de instalaciones solares fotovoltaicas del Técnico Superior en Energías Renovables. 
El backend se encarga de gestionar la estructura de datos, las simulaciones de generación y consumo de energía, y el almacenamiento de proyectos y configuraciones de usuario.  
La aplicación va a ser usada por usuarios, que tendrán que iniciar sesión para poder acceder a la plataforma de simulación. Cada usuario puede crear diferentes proyectos cuando está logueado, dichos proyectos tendrán un id, fecha de creación, nombre, y además dará información de si el elemento de consumo cubre las necesidades energéticas o no. Por otra parte, también hará un cálculo para avisar al usuario de que cantidad de energía es necesaria para que se cubran las necesidades energéticas.  
Cada proyecto puede tener una lista de elementos, tanto de consumo como elementos que generan energía, en este caso paneles solares. Los elementos guardan información general como el id, nombre y coordenadas en la pizarra de creación. Además, los elementos de clase panel guardan información adicional como la marca, la eficiencia energética y la energía que son capaces de generar a lo largo de un día.  
Por último, los elementos de consumo, además de guardar la información general de elementos, también almacenan información del consumo de energía que hacen en un día.  
Identificación de entidades y atributos descriptivos 
1. Placas Fotovoltaicas (Generadores) 
Refleja la entidad placa, donde cada uno de las instancias de las placas que se generen/almacenen tendrán su información individual asociada con su identificador así como su marca, nombre, potencia nominal (Wp) y eficiencia. 
Campos: 
? id_placa: identificador único de la placa (clave primaria). 
? marca: fabricante o marca de la placa. Tipo texto 
? nombre: modelo o referencia comercial. Tipo texto 
? potencia_wp: potencia máxima en vatios pico. Tipo Float 
? eficiencia: rendimiento de conversión energética del panel. Tipo texto ? coordenadas: lugar que ocupa en la pizarra de trabajo 
 
2. Elemento de Consumo 
En esta tabla se almacena la información correspondiente a los elementos de consumo que van a estar relacionados con las placas. Cada elemento tendrá su identificador, nombre y consumo medio en vatios. 
Campos: 
? id_consumo: identificador único del elemento de consumo (clave primaria). Tipo int 
? nombre_instalacion: nombre o descripción de la instalación que utiliza la energía. Tipo texto 
? consumo_wt: cantidad de watios que consume el elemento. Tipo Float ? coordenadas:lugar que ocupa en la pizarra de trabajo 
 
3. Proyecto 
Un proyecto representa las relaciones que se establecen entre placas fotovoltaicas y los elementos de consumo. Es el usuario quien las crea y las administra. Contiene información general sobre el proyecto, su energía necesaria y faltante, así como el usuario responsable. 
Campos: 
? id_proyecto: identificador único del proyecto (clave primaria). Tipo int 
? nombre: nombre del proyecto. Tipo String 
? fecha_creacion: fecha de registro del proyecto.Tipo LocalDateTime 
? cubre: devuelve un booleano para saber si la energía es suficiente o no. tipo Boolean 
? energíaNecesaria: cantidad de energía requerida por el proyecto (en kWh o Wp). Tipo Float 
4. Usuario 
Contiene la información personal y de acceso de los usuarios registrados en el sistema.  Cada usuario puede crear y administrar múltiples proyectos fotovoltaicos. 
De momento no se implementan metodologías de seguridad como hashing de contraseñas. Se implementaran en la segunda evaluacion Campos: 
? id_usuario: identificador único del usuario (clave primaria). Tipo Long 
? nombreCompleto: nombre y apellidos del usuario. Tipo String 
? fecha_nacimiento: fecha de nacimiento. Tipo LocalDate 
? email: correo de contacto y autenticación. Tipo String 
? contraseña: credencial de acceso al sistema. Tipo String

Guía De Primer Contacto 
A partir de aquí estaremos trabajando directamente en el código con el ORM Spring Boot. Para la persona que vea el proyecto backend por primera vez, se hace esta guía rápida a modo de introducción. 
El proyecto principalmente consta de 4 carpetas y una clase iniciadora, que solo sirve para iniciar el proyecto. 
Las carpetas son: 
? models: Esta carpeta básicamente son las tablas que se crea en la base de datos. Se definen los atributos de la clase y contienen los constructores. 
? controllers: Son las funciones de las tablas para acceder e interactuar con los datos 
? repositories: Son las interfaces para que los controllers puedan interpretar las interacciones entre clases y tablas 
? config: dentro están las configuraciones del proyecto, de momento solo hay un CorsConfig, donde se configuran las peticiones de la API 
Para leer los scripts dentro de las carpetas, se recomienda verlos en el siguiente orden: 
model>controllers>repositories. 
Dentro de estas, la recomendación es seguir el flujo de la app, siendo: 
Flujo Administrador 
Crear un usuario administrador (User) >  
Este crea los elementos necesarios (ya sea ConsumerElement o GeneratorElement) >  
Terminamos 
Flujo Usuario 
Crear un usuario (User) > este crea un proyecto (Project) >  
Entra en Project y añade elementos (en forma de nodos, ProjectNode) > conecta los nodos, guardandolo en el proyecto (ProjectNodeConnection) > Terminamos.

Problemas de conexión: 
Cuando hay problemas con el acceso a la base de datos o alguna inconsistencia en los modelos o repositorios, nos podían aparecer: 
- error 403: El servidor entendió la petición, pero no hay permisos para hacer lo que queremos. 
- error 500: El servidor tuvo un fallo interno y no pudo procesar la petición. Error en el backend 
- error 415: El servidor no acepta el formato en el que enviamos los datos
