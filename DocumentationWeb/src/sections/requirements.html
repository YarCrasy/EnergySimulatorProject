Requisitos

Requisitos de usuario

Antes de programar se analizaron las necesidades reales del usuario del simulador, las peticiones del centro y el comportamiento esperado en herramientas similares. De ese análisis salen los requisitos funcionales, que describen lo que el sistema debe hacer, y los no funcionales, que describen cómo debe comportarse.

Requisitos funcionales

Las prioridades se clasifican como alta cuando el requisito es imprescindible, media cuando es importante pero no bloqueante, y baja cuando puede quedar como mejora posterior.

IDDescripciónPrioridad
RF-01Registro de nuevo usuario con validación de email y contraseña segura.Alta
RF-02Inicio de sesión con email y contraseña, generando un token JWT para acceder a recursos protegidos.Alta
RF-03Crear un proyecto nuevo desde el panel de proyectos.Alta
RF-04Agregar elementos de consumo al proyecto.Alta
RF-05Agregar generadores, especialmente placas solares, al proyecto.Alta
RF-06Conectar elementos entre sí dentro del simulador visual.Media
RF-07Modificar propiedades de elementos, como nombre, potencia, cantidad y parámetros propios.Media
RF-08Ejecutar una simulación energética consultando datos meteorológicos reales de Open-Meteo.Alta
RF-09Visualizar resultados de simulación: generación, consumo, déficit, excedente, balance y autosuficiencia.Alta
RF-10Guardar el proyecto para poder recuperarlo desde la cuenta del usuario.Alta
RF-11Eliminar un proyecto propio con confirmación previa.Media
RF-12Configurar ajustes geográficos: latitud, longitud, inclinación, azimut y días de exposición.Media
RF-13Administración de usuarios para rol admin: listar, crear, editar y eliminar cuentas.Media
RF-14Gestión del catálogo de elementos energéticos para rol admin.Media
RF-15Exportar o descargar informes de simulación.Baja*

* El requisito RF-15 se mantiene como mejora futura si la versión entregada no incluye todavía la exportación de informes.

Requisitos no funcionales

IDDescripciónObjetivo
RNF-01Disponibilidad del sistema.La aplicación debe estar funcionando la mayor parte del tiempo durante el periodo de uso educativo.
RNF-02Rendimiento.La página web debe cargar en menos de 3 segundos con una conexión doméstica estable.
RNF-03Seguridad.Autenticación mediante JWT, contraseñas guardadas con hash y rutas protegidas para usuarios y administradores.
RNF-04Accesibilidad.Contraste suficiente, etiquetas en formularios, navegación por teclado y uso de atributos semánticos o ARIA cuando sea necesario.
RNF-05Usabilidad.Un usuario sin explicación previa debe poder crear un proyecto y ejecutar una simulación siguiendo la interfaz.
RNF-06Escalabilidad.El diseño por capas debe permitir añadir más usuarios, proyectos y funciones en versiones futuras.
RNF-07Mantenibilidad.Código modular, documentado, con nombres claros y separación entre frontend, backend, Android y documentación.
