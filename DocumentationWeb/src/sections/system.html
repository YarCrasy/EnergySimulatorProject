Arquitectura

Funcionamiento y especificaciones técnicas

EnergySimulator se compone de tres capas: backend Java con Spring Boot, frontend web React/TypeScript y aplicación Android nativa en Java. Todas las superficies se comunican mediante una API REST protegida con JWT.

Backend

Spring Boot expone controladores REST, servicios de negocio, repositorios JPA, seguridad con Spring Security y generación/verificación de JWT.

Frontend web

React y TypeScript implementan la SPA con login, registro, proyectos, simulador visual, administración, llamadas Axios y rutas protegidas.

Android

La app Java implementa login, listado de proyectos y perfil de forma nativa. El simulador se reutiliza mediante WebView.

Flujo de autenticación

PasoResponsableDescripción
1Cliente web o AndroidEnvía email y contraseña al endpoint de login.
2Spring SecurityValida las credenciales contra la base de datos.
3BackendGenera un token JWT firmado si las credenciales son correctas.
4ClienteGuarda el token en almacenamiento local o contexto seguro de la app.
5ClienteIncluye Authorization: Bearer <token> en cada petición privada.
6BackendVerifica firma, expiración y permisos antes de conceder acceso.

Flujo de simulación

PasoAcciónResultado
1El usuario selecciona consumidores, generadores y almacenadores.El proyecto contiene nodos configurables en el canvas.
2Configura latitud, longitud, inclinación, azimut y días de exposición.El backend recibe parámetros geográficos y técnicos.
3El usuario pulsa simular.El frontend envía el proyecto y los parámetros a la API.
4El backend consulta Open-Meteo.Se obtienen irradiancia, nubosidad y datos horarios reales.
5El servicio calcula balance energético.Se generan generación, consumo, déficit, excedente y autosuficiencia.
6Se persiste la simulación.Se guardan SimulationRun y sus puntos horarios.
7El frontend recibe resultados.La interfaz representa métricas y gráficos.

Integración del simulador en Android

Android implementa de forma nativa las pantallas de autenticación, listado de proyectos y perfil. Para evitar duplicar el simulador completo, la app abre el simulador web en un WebView. Antes de cargarlo, inyecta el JWT del usuario autenticado en localStorage y cookies, de forma que la SPA se abre con sesión ya iniciada.

Esta decisión permite mantener un único simulador visual en React, garantizar coherencia entre web y móvil y reducir el esfuerzo de mantenimiento.
