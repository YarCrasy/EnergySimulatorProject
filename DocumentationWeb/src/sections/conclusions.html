Conclusiones

Opiniones y reflexión final

El proyecto ha permitido unir varias competencias del ciclo en una solución completa: modelado de datos, API REST, seguridad, interfaces web, aplicación móvil, pruebas y despliegue.

Una dificultad importante ha sido mantener sincronizados los modelos entre backend, web y Android. También exige atención la persistencia de diagramas, porque no basta con guardar un proyecto: hay que conservar nodos, posiciones, cantidades, conexiones y parámetros de simulación.

Logros alcanzados

  • Aplicación web funcional con proyectos, simulador visual y administración.
  • Backend REST con persistencia, seguridad y estructura por capas.
  • Integración de datos meteorológicos reales mediante Open-Meteo.
  • Aplicación Android conectada a la misma API.
  • Documentación final navegable y preparada para impresión.

Mejoras futuras

  • Exportación de simulaciones a PDF, Excel o informes comparativos.
  • Cálculos energéticos más avanzados y validación con datos reales de instalaciones.
  • Modo offline para Android y sincronización posterior.
  • Roles de empresa, colaboración entre usuarios y proyectos compartidos.
  • Soporte multiidioma y recursos de gamificación educativa.

Reflexión del equipo

El proyecto ha sido un reto técnico y de organización. Coordinar backend y frontend, resolver problemas de CORS en producción, mantener sincronizados los modelos y adaptar la interfaz a distintos tamaños de pantalla son aprendizajes que se consolidan al construir una solución real.

Nos llevamos aprendizajes concretos: escribir tests desde el principio ahorra tiempo, definir bien la API evita bloqueos entre equipos y una documentación cuidada no es un trámite, sino una ayuda real para quien mantiene el proyecto después.

En conjunto, EnergySimulator demuestra que una herramienta educativa puede acercar conceptos técnicos de energía solar de forma visual, práctica y accesible, sin depender de hardware específico ni de plataformas de pago.
