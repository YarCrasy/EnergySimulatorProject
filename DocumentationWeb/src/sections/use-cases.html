Casos de uso

Actores y casos de uso

Los casos de uso describen cómo interactúan los usuarios con el sistema. Se contemplan usuarios sin autenticar, usuarios registrados, usuarios autenticados, administradores y el servicio externo Open-Meteo.

Actores

ActorDescripción
Usuario no autenticadoPersona que todavía no ha iniciado sesión. Puede registrarse o acceder al login.
Usuario registradoPersona con cuenta activa que puede autenticarse con email y contraseña.
Usuario autenticadoUsuario con token válido que puede crear proyectos, diseñar sistemas y simular.
AdministradorUsuario con rol admin. Puede gestionar usuarios y catálogo energético.
Open-MeteoSistema externo que proporciona datos meteorológicos reales para la simulación.

Detalle de casos principales

CasoPrecondiciónFlujo principalExcepcionesPostcondición
CU-01 RegistroTener acceso a la aplicación.El usuario entra en registro, introduce nombre, email, fecha y contraseña; el sistema valida campos, crea la cuenta y muestra confirmación.Nombre con números o menos de 4 letras, email inválido o duplicado, fecha futura, contraseña sin complejidad suficiente o campos incompletos.El usuario puede iniciar sesión con sus credenciales.
CU-02 LoginTener una cuenta activa.El usuario introduce email y contraseña; el backend verifica credenciales, genera JWT y redirige al panel.Credenciales incorrectas, usuario inexistente o backend no disponible.El usuario accede a sus proyectos.
CU-03 Crear proyectoHaber iniciado sesión.El usuario pulsa Nuevo Proyecto; se abre el simulador vacío; añade elementos, configura parámetros, simula y guarda.Error de conexión, datos incompletos o fallo al guardar.El proyecto queda almacenado en la cuenta.
CU-09 SimularProyecto con elementos mínimos y parámetros geográficos válidos.El usuario lanza simulación; el backend consulta Open-Meteo, calcula generación, consumo, déficit, excedente y autosuficiencia; se guardan ejecución y puntos horarios.Faltan elementos mínimos, coordenadas inválidas, fallo de Open-Meteo o respuesta vacía del backend.Los resultados se muestran en la interfaz y quedan asociados al proyecto.
CU-12 Administrar usuariosUsuario con rol administrador.El admin entra en administración, consulta la tabla de usuarios y puede crear, editar o eliminar cuentas.Validaciones de registro incumplidas, cancelación de borrado o error de permisos.La tabla se actualiza con los cambios aplicados.
CU-13 Gestionar catálogoUsuario con rol administrador.El admin navega a receptores o elementos, crea uno nuevo, edita datos existentes o elimina registros tras confirmación.Faltan nombre o potencia, coordenadas inválidas o elemento referenciado por nodos existentes.El catálogo queda actualizado para el simulador.
